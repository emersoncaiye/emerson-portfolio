## 二、踩坑记录（持续迭代）

### #1 Hexo默认主题不支持多语言

- **问题**：默认主题没有语言切换按钮
- **解决**：放弃Hexo，改用Astro（框架级多语言支持，不依赖主题）
- **教训**：选框架时要先确认目标功能是"原生支持"还是"插件凑合"

### #2 Cloudflare Pages路径大小写404

- **问题**：本地 `zh/Resume.md` 正常，部署后访问404
- **解决**：所有文件夹名、URL路径统一全小写
- **教训**：本地环境可能不区分大小写，但生产环境会

### #3 AI生成的代码不能全盘接收

- **问题**：直接复制AI代码可能导致不理解就上线
- **解决**：每段代码先问"为什么这么做"，理解了再用
- **教训**：AI是加速器不是自动驾驶

### #4 Cloudflare Pages默认构建命令不对

- **问题**：部署后页面空白
- **解决**：构建命令改成 `npm run build`（或对应框架的命令）
- **教训**：部署平台不会自动识别你的框架，要手动配

### #5 移动端菜单折叠打不开

- **问题**：主题的移动端菜单按钮点了没反应
- **解决**：换了一个轻量级主题
- **教训**：桌面端测试通过不代表移动端可用，要双端验证

## 三、我的关键决策记录

这些决策是**我做的**，不是AI做的：

| 决策 | 选项 | 我选了 | 理由 |
|------|------|--------|------|
| 框架类型 | 动态站 vs 静态站 | **静态站** | 快、免费、不需要后台 |
| 多语言方案 | 插件 vs 手动建文件夹 | **手动建文件夹** | 更可控，出了问题知道去哪改 |
| 功能范围 | 全功能 vs MVP | **MVP**（免评论区、免搜索） | 先上线再迭代 |
| 部署平台 | GitHub Pages vs Cloudflare | **Cloudflare Pages** | 全球CDN、自动HTTPS |

## 五、经验总结（可复用到下一个项目）

1. **先问"最快的方案是什么"** — 不要直接开始写，花2分钟问AI选型建议
2. **每20分钟让AI总结一次进度** — 保持方向感，不跑偏
3. **遇到报错，复制粘贴给AI** — 不要自己猜，猜了也是白猜
4. **能复制粘贴的绝不手写** — 这是原则

## 七、工作流总结

```
我描述意图
    ↓
AI生成代码 → 我本地运行预览
    ↓
我判断：是否符合预期？
    ↓
  是 → 继续下一步
  否 → 告诉AI调整方向 → 重新生成
    ↓
所有步骤完成 → 一键部署到Cloudflare Pages
```

这套方法的核心不是"让AI替你写代码"，而是 **"用自然语言驱动开发，你始终保持判断力和所有权"**。
